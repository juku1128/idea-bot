一、專題介紹

用途、使用對象與核心功能

  • 專題名稱：大學生報告主題發想_搜集機器人（IdeaCatcher Bot）
  • 使用對象：大專院校學生、常需進行期末專題、分組討論或學期論文的同學。
  • 想解決的問題：大學生在日常通勤、走路、滑社群或睡前常靈光一閃冒出絕佳報告主題，但往往因為手邊沒專門工具或備忘錄散落，導致「點子常飛掉」。本 Bot 讓同學在最常用的 LINE 中即時隨手一句話記錄，並自動分類整理，還能一鍵生成報告大綱！
  • 核心功能：收到點子後即時記錄、智慧學科歸類，並能隨時調閱、篩選及一鍵產出 Markdown 三段式報告大綱草稿。

三、開發過程

計畫、開發、修正與測試紀錄

  1. 需求確立與計畫撰寫：分析大專生主題收集痛點，定調單一核心功能，撰寫六大計畫項目。
  2. 核心邏輯開發 (v1.0)：完成第一版點子記錄與清單調閱，並於 Git 建立初版提交（Commit 1: 4dc5fe7）。
  3. 發掘痛點與升級功能 (v2.0)：使用者指出「點子只收集還不夠，能直接生大綱才實用」，因此鎖定實作「一鍵生成 Markdown 報告大綱草稿」與「智慧學科自動分類」，並捨棄過度複雜的外部 LINE Webhook 伺服器建置。
  4. 邊界防呆與例外捕捉：加入大綱與刪除之編號越界防呆，杜絕未預期崩潰。
  5. 自動化驗證與網頁整合：更新 test_bot.py 通過 5 項單元測試，並在網頁模擬器中加入大綱生成測試按鈕。
四、AI 協作

使用工具、代表性指令與檢查修正 AI 的真實經驗

  • 使用 AI 工具：Antigravity Agent (Google DeepMind)。
  • 代表性提示指令 (Prompt)：
    「請依照我的 LINE Bot 專題資料，實作一鍵生成 Markdown 報告大綱草稿功能，並加上智慧關鍵字自動分類、防呆捕捉與自動化單元測試。」
  • 檢查或修正 AI 產出的真實經驗（重要評量重點）：
    【真實經驗 1：修正 Git 初始化與目錄架構】
    最初 AI 在背景嘗試直接執行 git add，但遇到 macOS 沙盒權限確認。我察覺此資料夾應全新獨立管理，因此按下拒絕，並主動指示 AI「GIPINIT這個新的資料夾」，促使 AI 在獨立的「嘻嘻」資料夾中重新建立乾淨的 Git 倉庫，並於外層加入 .gitignore 隔離，有效避免兩個專案衝突。

    【真實經驗 2：精準聚焦改善項目，拒絕過度複雜規劃】
    AI 先前曾列出「串接 LINE Messaging API 與 Webhook 雲端部署」等未來項目，我及時審查並明確指出「該項目未討論且過於困難，本作業應交付改版完成品」，並指定實作「一鍵匯出 Markdown 報告大綱草稿」，讓專案精準聚焦在最有價值的實用功能上。

    【真實經驗 3：堅持真實性原則，杜絕虛構】
    我特別要求 AI：「裡面的內容若有缺漏請不要自行編造，請詢問我讓我補上。」促使 AI 主動全面盤點專案中的外部連結與個人心得，凡未確認者一律標註「待補」，落實了嚴謹求實的工程態度。
