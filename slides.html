大學生報告主題發想_搜集機器人

英文名稱：IdeaCatcher Bot (v2.0 改善完成版)

👥 目標使用對象：

大專院校在學學生、常需進行通識報告、專題研究或跨組協作之期末受難同學。

💡 核心訴求：把每個人在生活中冒出的「靈光一閃」，直接轉化為具有學術架構的成果。
⚡ 想解決的核心痛點
  • 💨
    靈感稍縱即逝
    搭車、洗澡、滑社群時常冒出絕佳題目，但沒即時工具記錄，常常「點子全飛掉」。
  • 📂
    隨手筆記零散混亂
    記在手機備忘錄或聊天室草稿，沒有分類架構，期末需要時宛如大海撈針。
  • 📝
    有題目卻卡在立大綱
    有了想法卻不知如何開頭撰寫背景、三大探討面向與結論，往往拖延到期末最後一刻。
✨ 核心解方：LINE 隨手一句話記錄 + 智慧分類 + 一鍵生成 Markdown 深度報告大綱草稿！

重點 4 · 人機協同真實經驗

AI 如何協助，以及我如何檢查與修正

Slide 4 / 5
🤖 使用工具：Antigravity Agent (Google DeepMind) ｜ 協助範疇：核心模組架構、正規表達式解析、測試腳本與網頁建置。
🚨 真實修正 1：糾正大綱千篇一律與智慧識別失敗 [核心除錯]

發現問題：實測「機器人」與「體罰世代」時，AI 最初產出的兩份大綱骨架完全一模一樣（公版三點式），且智慧系統未能正確推斷類別。
主動修正：及時抓出詞庫缺少「機器人」且「學生」字樣干擾判斷。要求 AI 重構大綱引擎，依領域產出深度客製化研究面向，徹底擺脫死板樣板！

📁 真實修正 2：掌控目錄獨立性與 Git 初始化 [架構掌控]

發現問題：AI 初期嘗試在外層全域直接 git add，觸發 macOS 沙盒權限提示，容易造成舊專案混雜。
主動修正：我明確按下拒絕並指示「GIPINIT這個新的資料夾」，促使 AI 在「嘻嘻」獨立目錄建立全新乾淨 Git 倉庫，並加上 .gitignore 嚴格隔離。

🎯 真實修正 3：拒絕過度規劃，鎖定實用改版 [需求定錨]

發現問題：AI 先前曾自行列出「串接 LINE Messaging API 雲端 Webhook 伺服器」等複雜未來願景。
主動修正：我明確告知該項目未討論且難度過高，作業應交付改版完成品，引導 AI 聚焦在最具實質效益的「一鍵生成 Markdown 報告大綱草稿」。

⚖️ 真實修正 4：嚴格落實求真，杜絕不實編造 [求真精神]

主動指示：我特別要求 AI「內容有缺漏請不要自行編造，請詢問我讓我補上」。
落實成果：AI 主動向我索取實際體驗與反思，個人姓名學號依隱私不公開原則處理，所有實測數據均經過實際執行驗證，絕不造假。

由人主導專案方向與品質把關，AI 作為強大執行槓桿與架構助手 符合作業獨立思辨與自主除錯要求

心得、限制與下一步 (v2.0 總結)

💡 真實學習心得
「我覺得用 Antigravity 寫程式真的可以學到很多新東西。像我之前較多是用 Gemini 的 Canvas 功能來寫，但他並不能幫我在本機內設計好程式，也不能直接連結到網路上、上傳 GitHub，也不太能具體和我解釋他到底修改了哪些地方。

但現在在操作 Antigravity 的過程中，只要有不懂的都可以詢問他為何這樣改，他也會解釋得非常淺顯易懂。更厲害的是可以自動幫我操作電腦，git 存檔、上傳 GitHub，甚至是自己完成程式測試與紀錄。真的非常厲害。」
⚠️ 現行限制 (Current Limits)
  • 通訊串接層次：目前以本機 Python CLI 與 Web 前端模擬器呈現，尚未向 LINE 官方申請付費企業 Webhook 伺服器部署。
  • 單機資料庫：目前點子以本地 JSON 儲存，尚未串接雲端關聯式資料庫，跨裝置使用需依賴網頁端。
  • 大綱知識庫來源：大綱由領域語意規則動態客製生成，目前尚未即時爬取當年度最新學術文獻期刊。
🚀 下一步 (Next Steps)
  • 學術文獻 API 串接：整合 arXiv / Google Scholar API，產出大綱時自動附上 3 篇真實權威期刊參考資料。
  • 多格式一鍵匯出：支援一鍵轉換為 16:9 簡報投影片檔 (.pptx) 與 Word (.docx) 期末小論文草稿。
  • Supabase 雲端多端同步：手機 LINE 隨手傳，筆電網頁即時編修大綱，實現無縫跨裝置體驗。
