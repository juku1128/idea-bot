## 💻 本機使用方法與實測操作

### 1. 執行自動化測試腳本 (單元測試與實測報告)
```bash
cd /Users/juku1128/Documents/測試/嘻嘻
python3 test_bot.py
```
> 執行後將印出包含「輸入內容、預期結果、實際結果」的實測報告，5 項測試全數通過（PASS ✅）。

### 2. 啟動命令列互動測試模式
```bash
python3 bot.py
```
在終端機中可直接輸入以下指令測試：
* **智慧記錄**：`靈感：深度學習在無人機的應用`（自動歸類為資訊科技）
* **指定分類**：`靈感：消費者心理學 分類：商管企管`
* **分類篩選**：`查看：資訊科技` 或 `搜尋：心理`
* **調閱全部**：`查看靈感`
* **單筆刪除**：`刪除：1`
* **防呆測試**：`刪除：99` 或 `靈感：`

### 3. 開啟開發紀錄網頁與擬真 LINE 模擬器
```bash
open index.html
```
* **LINE 互動模擬器**：網頁右側可直接打字或點擊快速按鈕進行實測。
* **成果簡報**：點擊右上角「🖨️ 匯出成果簡報/計畫 PDF」，即可一鍵匯出標準 5 頁簡報。

## 🤖 AI 協作與真實檢查修正經驗

* **AI 代理工具**：Antigravity Agent (Google DeepMind)
* **代表性指令**：
  > 「請依照我的 LINE Bot 專題資料，升級 bot.py 加入智慧關鍵字自動分類、領域篩選與單筆刪除功能，並加入嚴格的防呆捕捉與自動化測試腳本。」
* **檢查或修正 AI 產出的真實經驗（重要評量重點）**：
  1. **真實經驗 1：修正 Git 初始化與目錄架構**  
     最初 AI 在背景嘗試直接執行 `git add`，但遇到 macOS 沙盒權限確認。我察覺此資料夾應全新獨立管理，因此按下拒絕，並主動指示 AI「GIPINIT這個新的資料夾」，促使 AI 在獨立的「嘻嘻」資料夾中重新建立乾淨的 Git 倉庫，並於外層加入 `.gitignore` 隔離，有效避免兩個專案衝突。
  2. **真實經驗 2：堅持真實性原則，杜絕虛構**  
     我特別要求 AI：「裡面的內容若有缺漏請不要自行編造，請詢問我讓我補上。」促使 AI 主動全面盤點專案中的外部連結、姓名學號與個人心得，凡未確認者一律標註「待補」，落實了嚴謹求實的工程態度。
